# GraFx Studio: Rich text variables

![GraFx Studio icon](/assets/icon-GraFx-Studio.svg){.rn_icon}

Available from GraFx Studio **1.48**.

## ✨ New & Improved

### Rich text variables

A new variable type for text that arrives with its own markup — from a product information management (PIM) system, a content management system (CMS) or a data feed. Rich text import rules turn the tags into the paragraph and character styles of your template, so the source decides the structure and the template keeps it on brand.

- **Rich text** variable type, with a rule set assigned per variable
- **Rich text import rules**, managed per environment in GraFx Studio: map elements, optionally narrowed by attributes, to paragraph styles, character styles, line breaks, underline, strikethrough, subscript or superscript
- Build rules quickly by importing the paragraph and character styles of a Brand Kit
- Formatting stays inside the variable and doesn't affect the surrounding text
- Works in Run mode, Studio UI and output, and inside components

See [Rich text variables](/GraFx-Studio/guides/template-variables/rich-text/).

### Other improvements

- **Variable descriptions** — give a variable an optional description, for other designers and for GraFx Genie — see [Description](/GraFx-Studio/guides/template-variables/define/#description)
- **Layout intent in Actions** — the new `getLayoutIntent` helper function lets an Action react to print, digital static or digital animated layouts — see [Use the intent in Actions](/GraFx-Studio/concepts/layout-intent/#use-the-intent-in-actions)
- **Data injection fields** must have unique names, which keeps component mappings pointing at the right field — see [Data injection](/GraFx-Studio/guides/template-variables/data-source/#data-injection)
- **SDK**: set the shape of a shape frame, or of an image frame's container, to a rectangle, ellipse, polygon or custom SVG path

## 🐛 What's Fixed

- Fixed Actions reading the previous layout after a layout or page size change, which could leave frames shown or hidden incorrectly
- Fixed switching the connector of an image variable that is mapped to a frame with smart crop
- Fixed smart crop subject areas that could be saved slightly outside the image
- Fixed animation settings staying editable after switching from an animated layout to a non-animated one
- Fixed the **Available** toggle in layout settings not updating straight away
