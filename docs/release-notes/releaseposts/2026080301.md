# GraFx Studio: Data Source Variables

![GraFx Studio icon](/assets/icon-GraFx-Studio.svg){.rn_icon}

## ✨ New & Improved

### A new variable type: Data source

Until now, connecting a template to external data meant one thing: an **Output data source** that GraFx Studio iterates through row by row to produce a batch of outputs. That is exactly what you want for variable data printing, but it does not help when a single person needs to make a single piece of content — a sales rep picking their own name from the CRM, a store manager picking one product from the catalog.

The new **Data source** variable type closes that gap. It holds a reference to **one record**, chosen by the end user or set by an integration, and the rest of the template reads its columns like any other variable value.

Create it like any other variable: add a variable and set its type to **Data source**. Two things then need deciding.

**Where the records come from.** The **Select connector** dropdown in the **DATA SOURCE** section offers two options:

- **Connector** (the default) — records are read live from a [data connector](/GraFx-Studio/concepts/connectors-data/). Only connectors that explicitly support this use case appear in the list, so an existing connector may need a small addition before it shows up — see [Data Connector Fundamentals — Data Source Variable use case](/GraFx-Developers/connectors/data-connector/data-source-variable/data-source-variable-fundamentals/) in the Developer Center.
- **Data injection** — records are handed to the template by an integration at runtime. Because no connector describes the shape of that data, you define the columns yourself with **Manage fields**.

**How the end user picks a record.** The **Show variable as** setting controls this:

- **Table** — a modal with all columns and a row per record, browsable forwards *and* backwards. This is the familiar Output data source experience, now with two-way navigation.
- **List** — a plain dropdown showing one column of your choice, set with **Display Column**, loading further records as the user scrolls.

See [Data source variables](/GraFx-Studio/guides/template-variables/data-source/) for the full walkthrough.

!!! info "Two features, similar names"
    The batch feature previously called *Data source* is now consistently called **Output data source** — in platform settings, in Run mode, in Studio UI, and in output settings. It still exists and is unchanged. **Data source variables** are the new, single-record feature described here.

### Drive whole components from one record

A [component](/GraFx-Studio/guides/use-components/) placed in a template exposes its own variables, which you connect to template variables through a mapping. Those component variables can now be mapped straight to the **columns of a data source variable**, so selecting one record fills an entire component in a single step — a product card that populates its name, price, and image from the row the end user picked.

Select the component and click **Manage mapping** in the **Component** section to open the **Map component to variables** modal. Each component variable can now be mapped to a data source column, in addition to an existing or new template variable. The same type rules apply as elsewhere: a number variable maps only to a numeric column. Component image variables can be mapped to a text column, which is how imagery gets driven from a record.

Data source variables cannot be created *inside* a component — a component receives record data through mapping only.

### Keep internal component variables out of the mapping list

Components often carry variables that exist purely for internal plumbing — an intermediate value assembled by an action, a flag used by a visibility condition. Every one of those showed up in the parent template's mapping list, cluttering it with entries nobody should map.

A new **Available for mapping** toggle in a component variable's general settings controls this. It is on by default, so nothing changes for existing components; switch it off and the variable stops being offered to the parent template. If a variable was mapped and is later switched off, the mapping is simply not applied.

### Brand Kit sync, governed centrally

[Brand Kit sync](/GraFx-Studio/guides/brandkits/#keep-a-brand-kit-in-sync) keeps a template aligned with its source Brand Kit, and until now every template decided for itself whether that happened automatically. There was no way to answer the question "does automatic sync apply across this environment?" in one place.

**Environment Settings › General** now has a **Brand Kit sync settings** card with a single toggle, **Automatically update templates when Brand Kits change**:

- **On** (the default, and how every environment behaves today) — newly imported Brand Kits sync automatically, and an individual template can still opt out.
- **Off** — newly imported Brand Kits do not sync automatically, and the template-level toggle is shown disabled, so a template cannot opt back in.

Manual sync from the Brand Kit panel in GraFx Studio is unaffected either way.

For integrations, the setting lives in the environment settings under `applicationsConfig.brand_kits.features.default_sync`:

```
GET /api/v1/environment/{environment}/settings
```

```
PATCH /api/v1/environment/{environment}/settings
```

## 🔧 Improvements

### Smart Crop

Three refinements to setting up [Smart Crop](/GraFx-Genie/concepts/smart-crop/):

- **Snapping when centering the POI.** Dragging the Point of Interest toward the middle of the Subject Area now snaps to it, with dotted guides appearing while you drag and only when the POI is actually aligned. Centering the POI by eye was surprisingly fiddly; now it is one gesture. See [Set the Subject Area & POI](/GraFx-Media/guides/smart-crop-subject-area/).
- **Previews update while you drag.** The preview thumbnails in the image details panel used to refresh only once you released the handle, which made finding the right Subject Area a guess-check-adjust loop. They now update continuously as you drag, in both GraFx Studio and GraFx Media.
- **A cleaner properties panel.** The **Subject type** dropdown on an image frame is hidden when the environment defines no subject types beyond **Default**, since there is nothing to choose. It stays visible in the image details panel and in GraFx Media, where it signals that per-type Subject Areas can be set. See [Select a Subject type](/GraFx-Studio/guides/smart-crop/#select-a-subject-type).

### Component resize mode is inheritable

The **Resize mode** dropdown on a component frame — **Scale**, **Resize**, or **Scale and resize** — is now treated as an inheritable property. When a layout overrides it, the dropdown is marked in the usual warning color and the override can be reset like any other. The default is **Scale**.

### Faster editor loading

The web editor no longer waits for every font in a template to load before becoming usable. Fonts the template actually uses are still prefetched; unused fonts are fetched only if something needs them. Output generation continues to prefetch as before, so rendered results are unchanged.

### Superscript and subscript follow the font

As [announced in July](/release-notes/2026/07/15/upcoming-change-superscript-and-subscript-rendering-in-grafx-studio/), superscript and subscript text now uses the size and vertical offset defined in each font rather than a single fixed style. If your templates use this formatting, its appearance may change — that post explains how to check.

### Text and integration details

- **No forced break between variables.** Two variables sitting next to each other in a text frame no longer create a guaranteed line-wrap point in view mode, so text breaks where the words say it should.
- **A signal when the end user finishes editing a frame.** In project mode, the SDK now emits an event once a frame has been manipulated on the canvas — resized, rotated, cropped, or its text changed — reporting which frames changed. It fires after any actions triggered by the change have resolved, so integrations react to a settled document rather than an intermediate state.

## 🐛 Bug Fixes

### Colors and Brand Kits

Switching a color's type from CMYK to RGB or HEX left the color picker showing the wrong state. A Brand Kit theme color edited in a template is now synced back correctly after an update, and the sync flag no longer reports a sync that never happened. Smart Crop data is also refreshed properly when switching themes changes the asset on a frame.

### Text frames

Text frames show their loading indicator again while content is still loading — the previous behavior is restored. Enabling the **Allow inline text editing** constraint no longer redraws the frame with an overridden maximum height, which could change the layout of frames combining copyfitting and auto-grow.

### Components and actions

A component whose variable rules fail no longer crashes; the default resize mode for a component is correct again; action loops are now reliably detected; and resetting a layout animation override returns its duration information as expected.

### Output

A stroke applied to an image frame is now visible in PDF output. Invalid images encountered during PDF generation are reported as an in-flight error for that record instead of failing the whole job, so one bad asset no longer takes down an entire batch.

### Interface

The design of the animation reset block has been corrected.
